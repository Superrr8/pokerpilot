# PokerPilot — поэтапный план работы через Codex

Цель этого файла — уменьшить расход лимита Codex. Большие требования находятся в `POKERPILOT_MASTER_SPEC.md`, постоянные правила — в `AGENTS.md`. Каждый запрос ниже можно делать коротким.

---

```text
2. какие ещё не реализованы;
3. есть ли противоречия между документами и кодом;

```

- Codex понял документы;
- не изменил код;
- отметил расхождения.

## Этап 1. Усилить регрессионные тесты ядра

**Режим:** Medium  
**Цель:** прежде чем рефакторить код, создать надёжную математическую страховку.

### Требования

Добавить отдельные группы тестов:

- exhaustive 5-card evaluator;
- best-5-of-7;
- range counts and blockers;
- pot odds / required equity / EV;
- exact turn and river equity;
- seeded Monte Carlo;
- outs classification;
- invalid inputs.

Полная проверка 2,598,960 комбинаций должна запускаться отдельной командой, чтобы не замедлять быстрые тесты.

### Запрос Codex

```text
Выполни Этап 1 из CODEX_ROADMAP.md.
Следуй AGENTS.md.
Сначала покажи план и ожидаемые новые тестовые файлы.
Не меняй покерные алгоритмы, интерфейс, localStorage и сценарии.
После добавления запусти быстрые тесты и отдельный exhaustive evaluator test.
Не публикуй проект.
```

### Готовность

- быстрые тесты зелёные;
- exhaustive evaluator зелёный;
- алгоритмы не менялись.

## Как экономить лимит Codex

1. Всегда работать в одном проекте.
2. Не просить заново пересказывать всю архитектуру.
3. Ссылаться на этот roadmap и `AGENTS.md`.
4. Использовать Light для чтения и малых правок.
5. Использовать Medium для обычной реализации.
6. Использовать High только для математики, архитектуры и релизной проверки.
7. Не запускать параллельных агентов.
8. Не просить длинный отчёт, когда достаточно чисел тестов и списка файлов.
9. Не смешивать несколько этапов в одном запросе.
10. После каждого этапа делать backup или commit.
