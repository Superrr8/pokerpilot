# PokerElevate Release Provenance Register

## Scope and evidence standard

This register covers the browser product shipped from the PokerElevate repository before native packaging. It records repository evidence, not a legal conclusion. Git history and the presence of a file in this repository do not by themselves prove ownership. Items marked **operator attestation required** need a signed or otherwise durable confirmation from the release owner before App Store submission.

Baseline reviewed for this register: Stage 13.6B commit `2767656c8832e73ba72a18d90c1170ea9d528d6c` plus the Stage 13.6C repository changes.

## Production code

- Scope: `index.html` and production JavaScript under `src/`.
- Repository evidence: no package manifest, vendored library directory, minified third-party bundle, CDN script, remote module import, or copied copyright header was found.
- Runtime dependencies: browser platform APIs only, including DOM, Web Audio, vibration capability detection, storage, and standard JavaScript APIs.
- Rights status: repository-origin implementation; **operator attestation required** for contributor ownership/assignment and any code incorporated before the available history.
- License status: no third-party runtime code license notice was identified as required by the current source tree.

## UI and CSS

- Scope: `index.html` and `src/styles/`.
- Repository evidence: UI components, themes, poker table, cards, controls, layout, motion, and the PE mark are implemented in project HTML/CSS without third-party UI kits or icon packages.
- Rights status: repository-origin implementation; **operator attestation required**.
- Validation screenshots are not application inputs and are excluded separately below.

## Poker educational content

- Scope: `src/data/learning-course.js`, `src/training/`, explanations in `index.html`, and localized presentation in `src/ui/translations.js`.
- Repository evidence: no source citation, publisher excerpt, book title, training-site attribution, or third-party copyright header appears in the shipped content.
- Rights status: the repository cannot prove independent authorship of prose. The release owner must attest that educational wording is original or document every licensed source before submission.
- Claims boundary: content is presented as education and heuristic/exploit training, not professional advice, guaranteed profit, or absolute GTO proof.

## Ranges and scenarios

- Scope: `src/data/preflop-ranges.js`, `src/data/postflop-scenarios.js`, `src/daily/daily-challenge-catalog.js`, and deterministic trainer fixtures used by production behavior.
- Repository evidence: ranges and scenarios are local structured data and do not name a commercial poker room, solver, course, author, or publication as their source.
- Rights status: strategic facts and calculations are implemented locally, but the specific selection, wording, and arrangement still require **operator attestation** that they were not copied from a protected chart, course, database, or solver export.

## Generated audio

- Scope: `src/audio/sonic-identity-assets.js`, playback modules under `src/audio/`, and the deterministic source recipe `tools/audio-audition.cjs`.
- Repository evidence: the production micro-audio is PCM generated by the repository tool from deterministic mathematical envelopes and oscillators. The source contains no file import, sample-pack reference, recording, random sample selection, or third-party audio URL.
- No third-party audio samples are present in the production asset module.
- Rights status: no external sound license was identified as required. **Operator attestation required** that the generation recipe and its parameter design are project-origin.

## Branding and monogram

- Scope: `src/config/product-brand.js`, textual PokerElevate wordmarks, and the CSS-rendered `PE` monogram.
- Repository evidence: no external logo image or third-party brand asset is shipped. Legacy `PokerPilot` names remain only in compatibility APIs, storage keys, internal documentation, and historical identifiers where changing them would risk user data or compatibility.
- Rights status: visual implementation is repository-origin; **operator attestation required**.
- Trademark status: PokerElevate name clearance is not proven by repository evidence and remains an external trademark-search/legal task.

## Fonts

- The web product ships no `.woff`, `.woff2`, `.ttf`, or `.otf` file and imports no remote font stylesheet.
- CSS uses system/local fallback stacks. `Inter` is named as an optional locally installed face but is not distributed by this repository.
- No bundled-font attribution is currently required. If native packaging later embeds a font, its exact file and license must be added to this register and any required notice bundle.

## Unicode symbols

- Card suits, arrows, checkmarks, interface glyphs, flags, and emoji are Unicode characters rendered by the user’s platform fonts.
- No third-party icon font, emoji image set, or card-face image pack is shipped.
- Platform-rendered Unicode characters do not create a repository asset-license notice. Native packaging must re-audit if symbols are replaced with image artwork.

## Production assets

- Shipped identity/audio assets are code-native: CSS surfaces, textual marks, Unicode symbols, and generated PCM embedded in JavaScript.
- No production image, video, screenshot, external sound file, or downloaded font is referenced by `index.html` or `manifest.webmanifest`.
- The PWA manifest contains product metadata only and currently declares no icon files.

## Third-party and open-source inventory

- No `package.json`, dependency lockfile, vendored dependency folder, runtime framework, analytics SDK, advertising SDK, tracking SDK, or external API client exists in the current web product.
- No third-party license header or attribution requirement was found in shipped source.
- There is no license file granting reuse of PokerElevate source. Absence of a license file is not proof of ownership and does not replace contributor assignments or third-party clearance.
- GitHub Pages is the hosting provider, not code embedded in the application. Its service terms are an operator/hosting dependency rather than an in-app license notice.

## Validation artifacts

- Historical files under `artifacts/` were validation-only screenshots and were not referenced by production HTML, CSS, JavaScript, or the manifest.
- Stage 13.6C removes them from the deployable branch and adds `artifacts/` to `.gitignore`, preventing validation captures from becoming public GitHub Pages assets again.
- Historical copies remain recoverable from pre-Stage 13.6C Git history; they must not be reused as App Store marketing screenshots without a separate accuracy, fictional-data, privacy, and rights review.

## Required provenance sign-off before native release

1. The release owner must attest to ownership or valid licensing of production code, UI/CSS, educational prose, ranges/scenarios, audio recipe, and branding.
2. Every contributor or contractor must have an appropriate rights assignment or license on file outside this repository.
3. Any future dependency, font file, icon, image, recording, screenshot, or copied text must be added here with source, author, license, version, and required notice.
4. App Store screenshots and previews must be generated from the release build, contain fictional/local test data, and be reviewed independently from historical validation captures.
5. PokerElevate trademark clearance must be completed externally before final store metadata is locked.
